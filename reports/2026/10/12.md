## 最值得发 X 的候选主题

### S-001 Agent Lightning｜建议：立即发（注明研发方成绩）
A 极简观点版：
> 微软 Agent Lightning 有个值得研究的思路：直接用现有 Harness 做 RL 训练，不再重写一套 Agent loop。训练系统通过 LLM Proxy 采集轨迹。真正难的，是样本对齐、奖励归因和执行调度。

B 个人观察版：
> 最近在研究 Harness 和 RL 怎么结合，Agent Lightning v1.0 很值得读。它把现有 Agent 留在原来的执行环境里，训练系统只接管模型调用和 rollout。我尤其关心 rollout-level 的归因和成本，这部分比单个榜单分数有参考价值。

C 趋势/反直觉版：
> 让 Agent 通过 RL 变强，训练框架未必需要重写 Agent。Agent Lightning 把真实 Harness 保留下来，也暴露了新的难题：上下文裁剪、子 Agent、样本拆分会影响训练统计。训练和运行的一致性开始成为工程变量。

### S-002 Harness × Augment｜建议：立即发（不暗示全公司收购）
A 极简观点版：
> Harness 收购了 Augment Code 的部分资产，包括 Cosmos、Auggie CLI 和 Code Context Engine。这个动作挺值得看：Coding Agent 继续向测试、部署、运行和成本管理延伸，软件最终交付比代码生成更重要。

B 个人观察版：
> 一直在关注 Coding Agent 最后怎么走进企业。Harness 这次买下 Augment 的部分产品和技术，我觉得很有代表性：Agent 生成代码后，还有测试、安全、发布、回滚和审计。链路接不起来，任务就还没真正完成。

C 趋势/反直觉版：
> Coding Agent 很强，交付链路却可能还是碎的。Harness 收购部分 Augment 资产后，想把“从需求到代码”和“从代码到生产”接到一起。下一阶段的差异化，可能会更多出现在质量门禁、治理和 Cost/Task 上。
